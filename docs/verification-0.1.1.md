另行从修订后的源码重新构建了 25.12.2，成品再次通过分区检查、421 个软件包的安装数据库核对及 SeaBIOS 启动测试。该次启动中，内核对 `/boot` 记录了两个挂载条目，`/mnt/sda1` 的计数为零。磁盘分区表中只有一个 512 MiB 启动分区。

## 本轮修复

- 修改备份、过滤目录或版本后，旧结果和旧 PVE 操作单失效。读取前检查网络路径及中间目录的链接或重解析点。
- 校验实际递交给 ImageBuilder 的副本，限制公开下载来源；缓存使用内置发行记录或本机启动验收凭据。显式导入有哈希固定值的 ZIP 时，也核对同版本缓存的具体构建身份。
- 私有恢复先查运行目标与路径，再处理普通文件和账号。已有的符号链接、硬链接或挂载点不能把恢复内容引向其他数据。完成后核对 UCI、ADH 配置和实际代理核心。检测到上次写入中断时，操作单引导接回旧盘或重新导入干净系统盘。
- PVE 助手监测导入期间原配置、源文件、卷大小和 VM 状态的变化。结果不明确时保留卷供本地核对。

## 生产交换前后的检查

停机前准备可独立访问 PVE 的有线电脑、包含所有原有磁盘的独立整机备份，以及故障前的完整配置备份。记下现场的卷 ID、原启动顺序、LAN/WAN 网卡和 VLAN。保持两张网卡隔离完成恢复，在只接新系统盘的情况下冷启动，再依次验证 LAN、WAN、DNS、订阅、IPv6、VPN 和自己使用的转发规则。

测试使用公开固件和合成配置。真实订阅、ISP、PVE 集群存储以及旧机外置 extroot 的完整硬件状态需要在本地验收。旧卷保留为 Unused，直到真实业务通过并生成包含新系统盘的成功备份。

遇到 DNS 问题，先等 OpenClash 完成启动；它在 Mihomo 开始监听后还可能重启 dnsmasq。请从独立 LAN 客户端向原网关再查一次。测试中使用特殊用途网段作 LAN 时，本机解析正常，客户端查询却在透明代理中回到本机而失败。恢复了常规私网测试地址后，同一项检查通过。现场如有类似现象，可对照操作单核对本地网段的绕过和 DNS 劫持设置。
